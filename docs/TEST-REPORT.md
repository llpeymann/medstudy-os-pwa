## ۲. آزمون‌های عملکردی — ۲۱/۲۱ موفق

هر مجموعه یک‌بار روی Vite توسعه و یک‌بار روی build تولیدی از زیرمسیر واقعی
`/medstudy-os-pwa/` اجرا شد. در هر دو اجرا ۲۱ سناریو موفق و خطای Console صفر بود.

سناریوها شامل این موارد بودند:

- ساخت درس، فصل و مبحث
- وضعیت مطالعه و تسلط
- مرور موعدرسیده و ثبت مرور
- ثبت تست، درصد و دفترچه اشتباهات
- ساخت و انتقال وظیفه روزانه
- تغییر و ماندگاری تم
- ماندگاری داده پس از reload
- تاریخ آزمون و شمارش معکوس
- تهیه و بازیابی فایل JSON و رد فایل نامعتبر
- نمای موبایل، زبان فارسی و RTL

## ۳. build و PWA — موفق

```text
npm run build:pages   موفق؛ 1608 module
JavaScript            319.59 kB (94.00 kB gzip)
CSS                    40.92 kB (8.82 kB gzip)
npm run test:pwa      همه بررسی‌ها موفق
```

اعتبارسنجی artifact موارد زیر را پوشش داد:

- مسیر همه assetهای HTML زیر `/medstudy-os-pwa/`
- وجود فایل‌های ارجاع‌شده و نبود مسیر اشتباه از ریشه دامنه
- `start_url` و `scope` نسبی در manifest
- آیکون‌های واقعی ۱۹۲ و ۵۱۲ پیکسل و purpose نوع maskable
- ثبت Service Worker با `BASE_URL`
- cache فقط برای same-origin و محدوده برنامه
- نبود source map، داده تست، `.env` و فایل دسکتاپ در artifact
- اجرای واقعی زیرمسیر با Service Worker فعال
- manifest بدون خطا و فهرست installability errors در Chromium برابر صفر
- reload آفلاین و نمایش موفق داشبورد

## ۴. امنیت وابستگی‌ها

- `npm audit --omit=dev`: **صفر آسیب‌پذیری production**
- audit کامل: **۶ finding در ابزارهای توسعه** (۳ moderate، ۱ high، ۲ critical)
  در زنجیره Vite/Vitest/esbuild/tinypool
- ابزارهای آسیب‌دیده وارد JavaScript منتشرشده نمی‌شوند و سرور توسعه پیش‌فرض فقط
  روی loopback اجرا می‌شود.
- رفع خودکار نیازمند major upgrade است؛ به همین دلیل `npm audit fix --force`
  اجرا نشد و ارتقای major بدون مهاجرت و آزمون جداگانه انجام نشد.

## ۵. محدودیت‌های باقی‌مانده

- نصب واقعی از prompt مرورگر روی دستگاه موبایل اجرا نشده است.
- HTTPS و رفتار PWA روی نشانی عمومی فقط پس از deploy موفق قابل تأیید نهایی است.
- نتیجه تست آفلاین مربوط به build تولیدی محلی روی origin امن localhost است؛ نه URL
  عمومی که تا پیش از انتشار 404 برمی‌گرداند.
